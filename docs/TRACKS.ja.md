# コースを作る

*[English](TRACKS.md)*

キャプチャの上に自分のコースを組んで、配れる形にするまで。キャプチャを入れるところまでは
[SCENES.ja.md](SCENES.ja.md)、導入と操作は [USAGE.ja.md](USAGE.ja.md)。**このファイルは
その 2 つの間** — 絵が出るようになってから、人に渡せるトラックになるまで。

VelociDrone のトラックエディタそのものは説明しない（ゲームの機能なので）。ここに書くのは
**VDGS が絡む部分だけ**。

---

## 順番が全部

**名前を決める → 紐付ける → 組む。** この順でないと余計な手戻りが出る。

**表示はトラック「名」だけで決まる**（`bindings.json`）。だから：

- 組んでから名前を変えると、**紐付けが切れて絵が消える**。バインドし直せば戻るが、
  配布物の `bindings.sample.json` は配布時の名前を前提にしているので、**配る予定があるなら
  最初に決めた名前で通す**
- エディタに入る前に紐付けておけば、**組んでいる間ずっとキャプチャが見えている**

## 1. シーナリーを選ぶ

トラックは VelociDrone のシーナリーの上に載る（`scene_id`）。**キャプチャはそのシーナリーの
原点を基準に置かれる**ので、`scene_id` は「配ったトラックがキャプチャと同じ場所に来るか」を
決める数字でもある。

**平らで空のシーナリーを選ぶ。** ゲーム側の地形や建物があると、キャプチャと取り合いになる
（`SplatBackdrop` がキャプチャを黒い箱で囲うのは、外側の世界を見せないため）。

自分の環境で何番が何かは、これで見える：

```powershell
VDGS.exe --export-track --list
# [local]  scene  16  VDGS FDF
# [server] scene  33  ...
```

**いま公開している VDGS のトラックは 3 本とも `scene 16`。** 番号がインストール間で同じかは
未検証なので、**番号ではなく `--list` で自分の環境の実物を見る**こと。

## 2. 先に紐付ける

キャプチャを置いて、トラック名に紐付ける。ブラウザ UI（`http://localhost:8777/`）が早い —
`01 CONTROL` で現在のトラックが出るので、**Bind shown splat to this track** を押すだけ。

手で書くなら `<game>/vdgs/bindings.json`：

```json
{ "My Track": ["my-capture"] }
```

**紐付けの無いトラックでは何も出ない。** 間違ったキャプチャを出すより無害だから。

キャプチャ抜きで飛びたいときは `-force-d3d12` を付けずに起動する。VelociDrone 自身の
ランチャーは付けない。D3D12 でないと splat シェーダーが unsupported になるので、キャプチャは
読み込まれもしない。

## 3. 置き位置を合わせる

`02 LIBRARY` で **Scale** と **Height** を動かす。**変更は `placement.json` に自動保存される**
ので、決まったらそのまま組み始めていい。

**置き位置はキャプチャのもので、コースのものではない。** シーナリーの原点基準なので、同じ
シーナリーに別のコースを作っても位置は共通。逆に、**配布された `placement.json` は配布元の
トラックに合わせてある**ので、自分でコースを組むならここで直す。

スライダーは対数。**高さは ±200m まで届く**（キャプチャによっては原点が地下 200m にある）。
正確な値は数値入力に打つ。

## 4. 組む

ゲームのトラックエディタで普通に組む。**mod はキーを 1 つも奪わない** — F7（シーン保存）も
矢印キー（オブジェクト移動）もゲームのまま。操作はブラウザから。

VDGS 側で効いてくるのは 3 つ：

- **`-force-d3d12` で起動していること。** 無いとキャプチャは 1 つも描かれず、理由も出ない。
  companion の `FLY` は必ず付ける
- **メニューに長居しない。** D3D12 でメインメニューに 5 分ほど放置すると**ゲームが落ちる**
  （mod を外しても落ちるので mod は無関係。詳細は [AGENTS.md](../AGENTS.md)）。
  組んでいる間はエディタかトラックの中にいれば起きない
- **表示の切り替わりで 1 フレーム止まる**（数十 MB を GPU に送るため）。`.ply` 直置きだと
  **毎回パースからやり直す**ので 400 万 splat で 13〜14 秒。**組む前に変換しておく**と、
  この待ちがほぼ消える（[USAGE.ja.md](USAGE.ja.md) の 4-2）

## 5. コリジョンを焼く

**焼かないと壁も床もすり抜ける。** 手順は [SCENES.ja.md](SCENES.ja.md) の 4 節。

**壁の厚みは速度で決まる。** 物理は 400 Hz で、150 km/h なら 1 ステップ 0.104 m 進むので
**厚さ 10 cm 未満の壁はすり抜ける**。焼くときの帯が voxel の 4 倍あるのはこのため。

ブラウザ UI の **show solid** で殻を可視化できる。中から壁が見えるかを確認してから決める。

## 6. 書き出す

```powershell
VDGS.exe --export-track "My Track" My-Track.track.json
```

**公式トラックサーバーから落としたトラックは書き出せない**（弾かれる）。作者のものであって、
こちらのカタログで配るものではないため。

出るのは `name` / `scene_id` / `type` / `value` の 4 つだけの小さな JSON。`value` は
ゲームが持っている文字列**そのまま**で、整形もしない（入れ直したとき元と 1 バイトも違わない
ようにするため）。FDF の実例で 3,772 バイト。

## 7. 配る

`catalog/entries/<id>.json` を書いて、固めて、上げる。全部 [catalog/README.md](../catalog/README.md)。

**サイズと sha256 は測って書く、手で書かない。** ダウンロードが途中で切れたか差し替えられたか
を見るのは digest だけなので。`tools/make-catalog.sh` が実物から測る。

**再配布できるキャプチャかどうかは先に決着させておく。** 表記の不在は許諾ではない。判断表は
[AGENTS.md](../AGENTS.md) の「splat データは配布できない。同梱もしない」。

## つまずくところ

| 症状 | 原因 |
|---|---|
| エディタに入ったのに絵が出ない | そのトラック名に紐付けが無い。または名前を変えた |
| エディタで**別の**キャプチャが出る | トラック名の取得が飛行 HUD のラベルまで落ちていて、**最後に飛んだトラック名**を返している。トラックを一度読み直す |
| 何をしても絵が出ない | `-force-d3d12` が付いていない。`vdgs-shaders` が 1MB 未満（焼き直し） |
| 壁をすり抜ける | `collision.bin` が無い。または壁が 10 cm より薄い |
| 配ったら位置がずれた | `placement.json` を同梱していない、または受け取り側がトラック名を変えた |
| 5 分ほどでゲームが落ちる | メインメニューに放置した（mod とは無関係） |
