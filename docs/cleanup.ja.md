# 屋外キャプチャの掃除と、splat から焼くコリジョン

JDL-2026-R5（AirVis 出力、300 万 splats、90×77m の屋外レース会場）で確立した手順。
屋内キャプチャ（playroom / drjohnson）とは前提が違うところだけを書く。

## 大きい splat は削除ではなく、ワールド Y で寝かせる

**これが一番高くついた誤り。** 地面近くの巨大 splat は、内側から見ると視界を包む霞だが、
**真上から見ると地面そのもの**。同じ splat が両方の役をしている。

削除すると霞と一緒に地面が消える。同一カメラで測った実測：

```
                     真上・フィールド内側        地上 1.5m
                     平均   暗い画素(<10)        平均
元                   73.96      0.33%           36.68   ← 霞で何も見えない
1m 超を削除            44.65     12.61%           13.92   ← 地面に穴
1m 超を寝かせる         58.08      0.98%           17.25   ← 両立
```

**寝かせ方は共分散を押しつぶして固有分解し直す。** 片方の軸を縮めるだけでは目標に届かない
——垂直方向の広がりは 3 軸すべての二乗和なので、1 軸を 0 にしても残りが残る：

```python
k = target_sigma_y / sigma_y            # splat ごと、1.0 で上限
M = I - (1 - k) * outer(up, up)
Sigma = R @ diag(s**2) @ R.T
Sigma = M @ Sigma @ M.T
lam, V = eigh(Sigma)                    # -> scale = sqrt(lam), quat = V
```

`.ply` の四元数の並びは `rot_0..rot_3 = (w, x, y, z)`（実測で確定）。

**判定に使うのは σ_y = sqrt(Σ_yy)** で、ローカルのスケール値ではない。`scale_0/1/2` は
splat 自身の軸の長さなので、**寝ている 1m の板と立っている 1m の板が同じ値になる**。
SuperSplat の「大きい splat を選ぶ」機能が使えないのはこのため。

実績値：`--max-sy 0.05`、`--min-size 1.0`（1m 超だけ）、`--kill-size 10.0`（10m 超は削除）。
26,998 個を寝かせ、312 個だけ削除。

## 判定は必ず 2 視点でやる

**低い視点だけで「霞が消えた」と読んだ変更が、真上では「地面が消えた」だった。**
片方の視点だけで通した掃除は、もう片方を壊している可能性が常にある。

最低限この 2 つ：

- **地上 1.5m、シーン内部**（霞・ベール）
- **真上、フィールド内側だけを切り出して**（地面の穴）

真上の測定は**周囲の何も無い空間を含めてはいけない**。巨大 splat はそこを筋で塗るので、
削除すると「62% が暗くなった」という数字が出るが、**その 62% のほとんどは元々データが
無い場所**。フィールド内側の長方形だけを切って測る。

## 被覆の重みは「最長軸の二乗」ではなく「2 大軸の積」

**一度これで判断を外した。** 全 splat を「半径＝最長軸の円」と見なすと、0.6m × 0.01m の
針が実面積の 60 倍に重みづけされる。その誤りで「寝た針が画面被覆の 70.66%」という
結論を出し、対策を打っても絵が変わらなかった。

凸体の平均投影面積は表面積の 1/4（Cauchy）で、楕円体では **2 大軸の積が支配的**。
正しい重みで測り直すと、支配していたのは針ではなく**細長さ 2 程度のずんぐりした
巨大 splat**（上位 100 個で 11.67%、面積 177 m²）だった。

```
視点からの被覆寄与 = (a * b) * f^2 / d^2 * alpha      a, b = 大きいほうから 2 軸
```

## SuperSplat の輪は描画ではない

編集画面に出る巨大な楕円の弧は**アウトライン表示**で、実際に塗られる絵ではない。
細長い splat は輪郭だけ巨大で、面積が小さいのでほとんど何も塗らない。独立実装
（antimatter15/splat）で同じカメラから描くと、**あの輪はどこにも無い**。

面積保存で丸める（2 大軸を幾何平均に揃える）と輪は消えるが、**絵は 0.6% しか動かない**
——タダなのでチラつき対策として入れておく価値はあるが、見た目の問題の解決ではない。

## コリジョンを掃除済み splat から焼く

**AirVis の `model.collision.glb` を変換するより、掃除済みの `.ply` から焼くほうがよい。**
`.ply` はすでに最終フレーム（鏡映・回転・スケール適用済み）にいるので、**座標系を当てる
工程がまるごと消える**。

```
1. Y を切る            地下の残骸はグリッドの半分を食い、地面の下に偽の殻を作る
2. 穴を合成 splat で埋める  ← コリジョン用は合成でよい（下記）
3. 太らせる             最小スケールを格子 1 セル分に底上げ ← 必須
4. gs_field_mesh.py     密度場 -> 等値面
5. decimate_mesh.py     三角形の予算まで間引く
6. clean_mesh.py        島の除去
7. mesh_to_glb.py -> glb_to_collision.py
8. CollisionTest.Run    巻き順を決める
```

### コリジョン用の ply は描画されない。合成 splat を使ってよい

**見た目用に合成 splat を作ってはいけない**（FDF で霞とチラつきが戻った。埋めるなら
実在 splat の複製）。**コリジョン用は別**——密度場の入力にしかならないので、体積さえ
あれば中身は何でもいい。

実測：AirVis 出力の時点で、地面帯の 2m セルの **62%** が「splat の面積の和 < セル面積」。
撮影と再構成の側の穴で、掃除のせいではない。

### 密度場は薄いシートを取りこぼす。必ず太らせる

**中央の地面が大きく抜ける症状の正体。** 3DGS の地面は σ_y が 2cm しかない薄いシートで、
格子間隔 0.12m に対して 6 分の 1。**格子点が Y 方向でシートから 0.05m（sigmas 2.5 × σ_y）
以上離れた柱は密度ゼロ**になる。格子点とシートの距離は最大 0.06m なので約 17% の柱が
外れ、**地面が滑らかなぶん外れる柱がまとまって大穴になる**。

細かくすれば直るが、2cm を捉えるには res 0.03 ＝ 120 億セルで不可能。**逆に太らせる。**
全軸の最小値を格子 1 セル分に底上げすると評価範囲が sigmas 倍に広がって柱が途切れない。
**密度の頂点は alpha のままなので iso のしきい値は変えなくていい。**

実測：最小軸 p50 が **0.0042m**（格子の 30 分の 1）。0.08〜0.12m に底上げして、
iso を超えるセルが **1,321,193 → 7,291,599（5.5 倍）**、メッシュの成分数が
**2,736 → 274**（地面がバラバラの破片からひと続きの面になった）。

**太いほうが物理的にも正しい。** 物理は 400Hz、150km/h で 1 ステップ 0.104m 進むので、
厚さ 10cm 未満の壁はすり抜ける。

### 地面の高さ推定は木で壊れる。最小値フィルタをかける

XZ 格子の各セルで「小さく濃い splat の Y の 10 パーセンタイル」を地面とするが、
**セル全体が樹冠なら、その 10 パーセンタイルは樹冠の底**。そこに合成円盤を置くと
**4m 空中の見えない壁**になる。

対処は地面格子への最小値フィルタ（3 回＝半径 3 セル）＋ならし 2 回。実測で高さ p99 が
**4.24 → 1.20m**、合成円盤の配置高さ p99 が **4.49 → 1.23m**。

**下げすぎは埋まるだけで無害、上げすぎは見えない壁。** 非対称なので下げる側に倒す。

### 寝かせた splat はコリジョンで空中の板になる

見た目には要るが、コリジョンでは**空中に浮いた平たい見えない壁**。コリジョン用の ply
からだけ落とす（見た目の ply は無傷）。条件は「大きい かつ 平たい かつ 地面から浮いている」：

```
smax > 0.3m  かつ  sigma_y < 0.1m  かつ  局所地面から 0.8m 超
```

実測 1,423 個、高さ中央値 2.36m。**地面近くの平板は残す**——被覆の計算でそれを数えて
「埋めなくていい」と判断したセルが穴になるため（順番が循環する）。

### グリッドの上限と、ステンシルのコスト

`gs_field_mesh.py` は **4 億セルで打ち切る**（`grid too large - raise --res`）。
90×77×13m で res 0.06 は 4.38 億でぶつかる。res 0.065 なら 3.45 億で通る。

**ステンシルは立方体**なので、**寝かせた 10m の円盤も 10m の立方体**として評価される
（厚さ 8cm でも）。1 個で 1.9 億セル。寝かせた splat を多く残すと焼きが極端に遅くなる。

### 巻き順は落下テストで決める。符号は使えない

`CollisionTest.Run` を両方の向きで走らせて比べる。JDL では 2 回とも**生成のまま**が勝った：

```
生成のまま  on surface 4, elsewhere 3, through 1   （粗い版）
反転       on surface 2, elsewhere 2, through 4
生成のまま  on surface 1, elsewhere 5, through 2   ずれ 0.001〜0.212 m（細かい版）
反転       on surface 0, elsewhere 6, through 2   ずれ 0.148〜0.372 m
```

**屋外では `on surface` の数が低く出る。** テストは「10 秒後に動いていたら失敗」と数える
ので、野原の凸凹で転がり続ける球が `ELSEWHERE ... still moving` になる。ずれが数 cm
なら面には乗っている。**判定に使えるのは 2 本の比較のほう。**

### プレビューの `FAIL - shell leaked` は誤報になりうる

`preview_meta.py` は「殻がキャプチャ全体を包んでいるか」を見るので、**コリジョン範囲を
見た目より意図的に狭く切ると必ず FAIL になる**。`spongy` 警告も三角形の予算を上げれば出る。

## 編集した ply は座標系を必ず確かめる

**SuperSplat の書き出しはフレームを保つ**（実測で 1cm 以内に 100% 一致）。ただし
`splat-transform` は読み込みで Z 軸 180 度回すので、**通した道具によって違う**。
切り出しなら元の部分集合になるはずなので、位置を格子ハッシュに入れて一致率を測れば
1 回で決着する。

## 道具

密度場と間引きは `scipy` / `scikit-image` / `fast_simplification` を要求する。**Mac には
入らない**（PEP 668 で `pip install` が拒否される）ので wsl4090 の
`~/jdl-collision-venv` で走らせる。62GB / 32 コアあるので 4 億セルでも余裕がある。

**待ちループに `pgrep -f <script>` を使ってはいけない** ——`bash -c` のコマンドラインに
そのスクリプト名が入るので**自分自身にマッチして永久に抜けない**。マーカーを書く：

```bash
nohup sh -c 'python bake.py ... > bake.log 2>&1; echo EXIT=$? >> bake.log' &
# 待つ側
until grep -q 'EXIT=' bake.log; do sleep 30; done
```
