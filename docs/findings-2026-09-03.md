# 2026-09-03 の発見 — 360 動画を COLMAP 4.2 と AirVis trainer で再構成

`VID_20260821_173728_00_007.mp4`（Insta360、5760×2880、284 秒）を COLMAP 4.2 の
panorama リグで再構成し、gsplat と AirVis の trainer で学習した記録。作業場所は
wsl4090 の `~/jdl-360-r2`、Windows 側は `%USERPROFILE%\jdl360-colmap` と
`jdl360-airvis-*`。

## 確定した結果

| 工程 | 値 |
|---|---|
| 抽出 | 2 fps → 568 パノラマ |
| 仮想視点 | 12 面 × 568 = 6,816 枚、`SIMPLE_PINHOLE 1440×1440 f=720`（16 px/度 ＝ 元動画の物理上限） |
| 空・人マスク | 空の平均 43%。上向き面は 88% |
| **SfM** | **6,732/6,816 枚（98.8%）、561/568 パノラマ、249,727 点、再投影 0.942 px** |
| gsplat 1M | masked PSNR **24.599**、不透明度 p50 0.030、生存 68.1% |
| gsplat 3M | **崩壊**（生存 0.2%） |
| gsplat 5M | `illegal memory access` で死亡、中間保存なしで全損 |
| AirVis 6M（safe） | 12 分、VRAM 5.2 GB、σ/シーン p99 0.04%（良品のゲート 1.88% より締まる） |

AirVis 自身の 360 単独（前回、生存 7.6%）と同じ素材で **生存 68.1%**。360 単独は
使えないという結論は覆った。効いたのは 4 つ：panorama リグ、空・人マスク、
`opacity_reg 0.001`（gsplat）、cap を画像数の範囲に収めること。

## 踏むと高くつく罠 — 全部エラーが出ない

- **画像を改名すると COLMAP のリグが壊れる。** フレームは「画像名から `image_prefix` を
  除いた残り」で束ねられる。`c00_00001.jpg` にしたら 1 フレーム 1 センサーに割れて
  50 モデルに分裂した。`step4_sfm.py` に fail-fast を入れてある
- **pycolmap の `mask_dir` は空マスク置き場ではない。** Voronoi マスクを自分で書く場所で、
  置いたものは上書きされる。空マスクは別ディレクトリで AND する
- **PyPI の pycolmap は `has_cuda: False`。** CUDA + Caspar 付きは `~/opt/colmap-4.2` と
  `.venv-colmap-cuda` に自前ビルド。pycolmap は `find_package(colmap)` で **システムの
  古い 3.13 の `.a` を黙って拾う**ので `-Dcolmap_DIR` で指す。`CMAKE_PREFIX_PATH` を `-D` で
  立てると scikit-build-core が注入する pybind11 が消える
- **gsplat の `pgrep -f`／PID 取り違えを 3 回踏んだ。** 自己一致、`env` ラッパー、
  DataLoader のワーカー。本体は tb イベントファイル名の PID で確認する
- **gsplat は 1440² で 3M を超えると 24 GB を使い切る。** `--packed` は序盤しか効かない
  （MCMC が cap に向けて育つ）。中間保存は消さない
- **gsplat の崩壊は正則化が固定だから。** AirVis のアプリは `opacity_reg` / `scale_reg`
  0.01 固定で成功、CLI の `conservative` は `scale_reg=0` で巨大 splat を作る

## AirVis の trainer は単体で叩ける

使い方・フラグ・罠（`--max-splats` 過大で preset が黙って落ちる、書き出し座標が COLMAP と
対応しない、ply のプロパティ順、OpenSSH のプロセス木殺し）は
docs/airvis.ja.md「trainer を単体で叩く」に集約した。ここには**この日に外した順番**だけ残す
—— 座標系の追跡に 2 時間超：符号付き置換 48 通り × 倍率 3 通り（最高相関 0.43、正解の
gsplat 1M は 0.89）→ ICP（平面優勢で偽解、残差は小さいのに相関 −0.13）→
`--align-to-first-camera true`（camera0 の枠が 1 枚で 0.56、2 枚平均 0.29）→ その枠からの
連続最適化（0.41）。**そもそも品質判定に自前カメラでの描画は要らなかった**（SuperSplat で
足りる）。手段を目的と取り違えた失敗。

## 判定（Saqoosha、SuperSplat で目視）

**AirVis 6M も gsplat 1M も、前より良いが使える品質ではなく、配備中の JDL（DJI 456 枚）にも
届かない。** 指標（生存率、σ 分布）が健全に見えても品質とは別物 —— 今日いちばん
読み違えやすい点。理由は撮影の物理で、設定では
埋まらない：仮想視点 16 px/度 対 DJI 63 px/度（3.6 倍粗い）、歩き撮りの動きブレが
均一（Laplacian 分散の p95/p50 が 1.51 倍、5 枚に 1 枚を選抜しても 1.15 倍）。
配備は JDL-2026-R5（DJI のみ）のまま。

**今日の資産は結果ではなく道具。** COLMAP 4.2 の panorama リグ（登録 98.8%）、AirVis
trainer の単体運用（自前 SfM を食わせられる）、gsplat のマスク parser。**まだ未検証の
唯一の合成案** —— 同じ COLMAP モデルに DJI 456 枚を 13 台目のカメラとして足し、地面の
被覆を 360 から、鋭さを DJI から取る —— は、この道具でようやく試せる状態になった。
